## 不要丢失的判断

- 当前生产发布为 v0.7.1，PyPI 与 GitHub Release 均已发布；wheel 已从正式 PyPI 在仓库外干净安装。完整服务仍依赖源码，不要说 wheel 已含 Collector/Dashboard runtime。
- S1–S4、B1/B2/H0 已包含在 v0.7.1 正式发布中，并通过该版本的发布验收。
- v0.7.1 已发布 retrieval/llm/tool span。tool 是调用方显式记录的同步步骤，不是通用 agent runtime。E3 需要调用方显式传入 Responses 对象；价格为有限模型范围的参考估算，不是账单。
- 用户希望从 RAG 调试适度扩展到 agent/harness 的执行效率；最新细纲提出“用量 → 疑点 → 修改 → 质量约束比较”的有限闭环，而非重写平台。
- 用户已同意按规划逐片开发，不是一次性授权所有未来功能。下一片始终以 CURRENT_TASK 为准，不在本入口重复维护阶段状态。
- 旧 A–D 计划中大规模跨领域 RAG 调优优先级已后移；不是要丢掉 retrieval 和现有证据能力。

## 怎样避免重复劳动

- 默认中文；给用户有依据的判断，而不是附和上一位模型。
- 每片先写简短决策卡，只追一个可展示的结果。普通已授权细节自己处理，方向扩大先说明。
- UI 尽早在真实页面验收；不能只交代码 diff 或 build 结果。
- 通过写定验收后结束；不要顺手补图表、抽象、兼容所有框架。
- 相关变更做相关测试；发布候选才做完整分发/全栈验证。不得跳过受影响的必要检查。
- 每片结束必须自检、记录 DEVLOG、更新 CURRENT_TASK 与 ROADMAP 进度；CURRENT_TASK 保持短，历史证据不复制进七个文件。
- 已知 Docker/WSL 环境限制不要反复重试；不要为 SDK/UI 工作擅改用户系统。
- E3 只有脱敏离线 fixture 与本地 Dashboard 证据，未做付费 provider 调用、账单对账或外部工作流验证。选择 E4 前先明确真实工作流和可观测的质量结果；roadmap 不是全量授权。
- PyPI 当前 0.7.1 页面使用的是不可变发行包中内嵌的旧 SDK README，仍有“when available”等发布前措辞；仓库 README 已改正。不要重传同一版本，后续发行应带上已更正的描述。

最后：1.0 的目标是别人能独立、反复完成一次有用的诊断与验证，不是实现全部 roadmap 名词。
