# Agent 方向：从参考取证转向可行动诊断

更新：2026-09-26，替代 9 月 25 日“先找一个工作流，再等两种 E4 重复规则”的活跃顺序。
原准备决定和运行证据保留在 DECISIONS/DEVLOG；本文件不宣称新功能已经实现。

## 当前判断

已发布 E2/E3 是显式步骤、结果与有限 usage 映射，不是通用 Agent runtime。
A1/A2 已有固定 PydanticAI 参考，E4P/E4R 提供合成重复样本与实际正常重复反例。
用户现已选定 MAMR 作为自己的内部试验应用；四次真实模型调用后的合同失败揭示了取证缺口。
它不是工具执行证据，不是外部采用，也未证明任何修复或节省。

不再找第三个 Agent 框架；也不再用“缺少重复浪费正例”阻塞确定性校验错误定位。

## 固定三个对象

| 对象 | 唯一主要用途 | 不能替代的证据 |
| --- | --- | --- |
| MAMR | 多 LLM 输出合同、流程暂停、原生取证、一次真实修复比较 | 工具 Agent 覆盖、独立用户采用 |
| PydanticAI 固定参考 | 实际工具执行、正常动态指令重复、未知 usage 边界 | 通用浪费准确率或全部框架支持 |
| 现有 RAG fixtures | 检索诊断、旧记录/兼容回归 | Agent 逻辑与任务质量验收 |

## 已采用的顺序

P1 校验原因 → P2 源头尝试证据 → P3 脱敏导入（存储/隐私前置）→
P4 D1 定位 → P5 比较 → P6 一次真实修改决定；P7 D2/D3 按需，不阻塞主线。
详细接受条件、工期和里程碑由 [ROAD_TO_V1_0](ROAD_TO_V1_0.md) 统一维护。

- D1 失败层级与明确影响链是必做。
- D2 相同失败无可见相关条件变化、D3 违反应用声明预算/停止条件是条件性候选。
- 相同工具结果只是观察，不必为 1.0 凑成报警。
- 来源未知、质量未评估、执行失败分别表达；缺字段弃权，不说“全部正常”。
- 原子保存/重复提交在导入前处理；不以变换 ID 掩盖重复计量。
- MAMR 跨仓库工作必须遵循其 AGENTS/任务与权限，本轮没有修改它。

## 证据与停止点

分别记录：确定性 fixture、公开参考离线运行、真实模型调用、内部真实开发帮助、外部独立重复使用。
真实性与采用独立性是两条轴，不把一次付费调用自动升级成产品价值。

确定性 validator 用分支/边界测试；D2 等启发式用提前留出的正反例；
P6 用固定任务/验收的结果比较，保留失败和额外尝试。不要把“8–12 个样本”作为一切开发的入口。

每次 live 写定问题、变量、验收、次数/费用与停止点；现有 $0.50 授权不是长期额度。
最多两轮有新证据的修复；连续两片无可见结果、两个合适真实场景无行动价值就复盘收窄。
不为重现已经缺失原始输出的历史错误无限测试，不追加图编辑器、语义裁判或适配器来绕过门槛。
