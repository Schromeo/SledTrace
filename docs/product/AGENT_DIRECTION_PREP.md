# Agent 方向准备：先取得证据，再实现 E4

状态：2026-09-25 的准备方案；不是已实现的 Agent 诊断，也不是 v0.8 发布承诺。

## 为什么暂不直接写规则

用户目前没有在用的 Agent 工作流。已发布的 E2 能记录调用方显式提交的
`llm`、`tool` 尝试与最终任务结果；E3 能在显式边界记录一次 OpenAI
Responses 的用量。仓库内 `agent_tool_demo.py` 是确定性单工具集成样例，
不能代表外部 Agent 的调用分布或诊断价值。后续草稿 PR #16 的一次
Federalist 模型调用是 RAG 证据，不是 Agent 执行。

因此把“技术路径跑通”和“开发者真的据此改进任务”分开验收。没有后者时，
E4 最多是受限候选，不声称已发现真实浪费或节省。

## 下一片：A1 选择并接入一个参考工作流

只选一个可公开获取、许可允许本地运行、单进程的 Python 工作流。
优先资料处理/检索加工具调用，保留其原本要完成的任务，不为了触发
告警故意加入循环。筛选时记录来源、固定版本、许可、依赖、数据来源和
任务结果；最多考察两个候选，用一个有效开发日决定继续或停止。

入选必须满足：

1. 不依赖私有数据、云账户或未获授权的付费调用即可运行一个完整任务；
   如模型不可离线运行，明确把替身路径标为技术 fixture。
2. 至少两次可区分的决策/模型步骤和一次真实执行的工具步骤；能观察
   参数、结果或安全摘要、顺序、成功/失败、时间及最终任务结果。
3. 有预先写定的任务 ID、输入、正确性/可接受性判据和可重复运行方式；
   不用 warning 数量定义质量。
4. 不要求 SledTrace 新增 Agent runtime、框架适配器、span 家族或数据库
   迁移。不能满足时记录缺口，不为这个样例扩大产品契约。

A1 的可见验收：运行该任务，现有 SDK → Collector → Dashboard 顺序展示
真实执行的步骤、最终结果及已知/未知用量；至少一条正常成功路径和一条
自然失败或恢复路径可复查。先用本地、无费用方式。若需要真实模型，单独
取得调用次数与预算授权。公开示例只验证接入和读数，不代表用户采用。

## E4 进入门槛与样本矩阵

只有 A1 给出稳定的事件/结果字段，才考虑两类保守提示：

| 候选提示 | 最低正例证据 | 必须保留的反例 |
| --- | --- | --- |
| 疑似重复工具结果 | 同一工具、可比较的规范化参数与结果指纹、步骤顺序及状态 | 正常轮询；外部状态已改变或不可见；必要确认 |
| 疑似重复失败 | 相同错误类别、可比较的参数/摘要、连续尝试且无已知条件变化 | 限流退避后成功；修正参数；状态改变 |

缺少比较字段时只显示已观察的步骤，不推断重复。摘要/指纹由调用方在
明确内容边界内提供，不悄悄保存原始私密参数。即使提示触发，也叫
“疑似、建议检查”，不计算“已浪费金额”。每类规则在修改前预留正反
和边界样本，至少一个触发例及两个合理重复反例须在真实页面可见。

## 证据等级与停止规则

- **L0**：仓库确定性 fixture——验证序列化、读回与 UI，不证明真实价值。
- **L1**：独立公开工作流的本地运行——验证接入摩擦和字段适配，不证明
  真实用户采用；若模型仍是替身，不称作真实模型执行。
- **L2**：经单独授权的真实模型运行——可检查该次用量和结果，不等于
  账单对账或总体诊断准确率。
- **L3**：外部开发者重复使用并据证据决定保留/撤销修改——才开始验证
  产品价值；同时记录质量约束与未成功案例。

如果两个候选都不能在上述边界内跑通，或连续两个切片没有新的用户可见
判断，停止扩张 E4，复盘接入阻力。不得靠增加第三个框架、Agent DAG、
语义裁判或更多规则来掩盖缺少真实任务。E5 的前后对比仍需等同任务和
预先确定的质量判据；不能用更低 token 数单独宣称优化成功。
