## S1 的原始接手依据（已经执行，不要重做）

本信最初要求从 CURRENT_TASK 的 **S1：span 计时可信度** 开始。该任务现已在工作树完成；以下文字保留设计缘由，不能再当作待执行清单。

已发现的问题很具体：在检索和 LLM 调用结束后，当前记录 API 才开始计时；模拟 80ms 和 120ms 的工作，trace 约 200ms，两个 span 却是 0ms。LLM 的显式 latency_ms 是现有能力，需继续兼容。

最容易踩的坑是：只把 duration_ms 改成 null 不够，Dashboard 详情还会从记录时间戳回推耗时。要区分已测、未知和真实零值，同时保持时间线、详情及总耗时的含义一致。事后记录 API 无法凭空恢复已经完成调用的时间；确切 API 设计由你根据最小兼容改动选择，完整验收见 CURRENT_TASK。
