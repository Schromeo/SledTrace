# SledTrace v0.7.1 — Trustworthy Local Tracing

SledTrace v0.7.1 is a backward-compatible reliability release for the existing
local-first Python SDK, Go Collector, SQLite store, and React Dashboard. It
focuses on making recorded evidence and local startup behavior more honest and
predictable; it does not broaden the product into a hosted platform.

## Highlights

### Trustworthy span timing

- Added public `SpanTiming` and `t.measure()` for measuring the actual retrieval
  or LLM operation with UTC boundaries and monotonic elapsed time.
- Preserved explicit retrieval `duration_ms` and LLM `latency_ms` inputs.
- Unmeasured post-hoc spans now remain unmeasured instead of reporting false
  near-zero durations.
- Dashboard timing treats unknown, measured zero, and legacy fallback values as
  distinct states and no longer substitutes a partial span sum for trace time.

### Retrieval score semantics

- Normalized chunks retain `score_type` and `score_direction` when known.
- Similarity/relevance scores remain higher-is-better; distance is explicitly
  lower-is-better; ambiguous tuple scores remain unknown.
- The Collector applies low-score thresholds and score ordering only where
  higher-is-better semantics are established. It does not invent a
  `1 - distance` conversion.
- The Dashboard labels score direction as `Similarity ↑`, `Distance ↓`, or
  unknown where appropriate.

### Observable trace delivery policy

- Existing synchronous `flush()` behavior remains strict and exception-raising.
- New `try_flush()` performs one synchronous delivery attempt and returns
  `TraceFlushResult(ok, response, error)` for ordinary failures.
- The original delivery exception remains inspectable, while callers can keep a
  telemetry failure from replacing successful business work or an existing
  application exception.
- No retry, queue, disk buffer, background worker, automatic logging, or
  auto-flush behavior was introduced.

### Safer local network defaults

- Native Collector, Vite development, and Vite preview listeners default to
  `127.0.0.1`.
- Docker Compose publishes Collector and Dashboard host ports on loopback by
  default while preserving container-internal listeners.
- Collector CORS defaults to the exact local Dashboard origins instead of `*`.
- Intentional remote access remains available through explicit binding, allowed
  origin, Dashboard API URL, and SDK Collector URL configuration.

## Install

After publication:

```bash
python -m pip install sledtrace==0.7.1
sledtrace version
```

The wheel contains the SDK and CLI. `sledtrace serve` still requires a SledTrace
source checkout; Collector and Dashboard runtime assets are not bundled in the
Python wheel.

## Compatibility

- Preferred Python import: `sledtrace`
- Temporary legacy import: `raglens`
- Preferred Collector URL variable: `SLEDTRACE_COLLECTOR_URL`
- Temporary legacy Collector URL fallback: `RAGLENS_COLLECTOR_URL`
- Implemented span types remain only `retrieval` and `llm`
- Collector API routes and SQLite schema remain compatible
- Strict `flush()` calls keep their existing return and failure behavior

Remote users who previously relied on all-interface defaults must now configure
the address/host and browser origins explicitly. Local SDK and command-line
requests without an `Origin` header continue normally.

## Local candidate validation

Completed before opening the release pull request:

- 62 Python SDK tests
- 0.7.1 wheel and sdist build plus Twine metadata validation
- clean-wheel preferred/legacy imports, CLI, timing, score, and delivery checks
- all Go Collector tests
- 10 Dashboard behavior tests and the production build
- default and intentional-remote Docker Compose configuration expansion
- nine live SDK → Collector → SQLite → Dashboard reference traces
- three refreshed 1440x950 screenshots captured from the real Dashboard

Still required before release:

- clean-clone startup smoke for the documented non-Docker path
- required protected pull-request checks on the exact remote candidate commit
- merge, immutable tag, protected PyPI publication, clean production-index
  installation, and GitHub Release as separately authorized release actions

Docker runtime smoke remains dependent on a host with working Docker
virtualization. Static Compose validation alone is not evidence that containers
started successfully.

## Not included

v0.7.1 does not add:

- authentication, TLS, cloud hosting, or multi-tenancy
- agent, tool, memory, retry, or streaming spans
- LangChain or LlamaIndex adapters
- LLM-as-judge or calibrated factuality scores
- delivery retries or atomic trace/warning persistence
- a standalone Collector/Dashboard runtime inside the Python wheel
