# SledTrace v0.8.0: install and run with pip

SledTrace v0.8.0 makes the local RAG debugger usable straight from PyPI. The
collector and dashboard now ship inside platform wheels, so two commands are
enough:

```bash
pip install sledtrace
sledtrace serve
```

No source checkout, Docker, Go or Node.js is needed. The SDK API, trace format
and warning rules are unchanged from v0.7.1, so existing integrations keep
working without edits.

## Highlights

### `sledtrace serve` works after `pip install`

- Platform wheels for Windows, macOS and Linux (x86-64 and ARM64) bundle the
  collector binary and the built dashboard (about 4 MB each).
- The collector serves the dashboard and the API on one address,
  `http://127.0.0.1:4319`, which is also the SDK's default collector URL.
- `sledtrace serve` waits until the collector is healthy, opens the dashboard in
  your browser, and stores traces in `~/.sledtrace/sledtrace.db`.
- It recognises an instance that is already running, refuses a port used by
  another program, and stops the collector on Ctrl+C or termination.
- New options: `--host`, `--port`, `--db`, `--no-browser` and `--source`.
- On platforms without a prebuilt wheel, pip installs the SDK-only wheel and
  `sledtrace serve` runs from a source checkout as before.

## Compatibility

- No changes to the SDK API, the trace payload, the collector HTTP API, the
  SQLite schema or the warning rules.
- Source and Docker setups behave as before. The collector serves a dashboard
  only when `SLEDTRACE_DASHBOARD_DIR` is set.
- The dashboard build uses the same origin as the API when
  `VITE_SLEDTRACE_API_URL` is explicitly empty; the default stays
  `http://localhost:4319`.
- `sledtrace serve` defaults to `~/.sledtrace/sledtrace.db`. Source setups keep
  using `raglens.db` in the working directory unless `SLEDTRACE_DB_PATH` is set.
- Legacy `raglens` imports and `RAGLENS_*` variables still work.

## Validation

- CI builds the platform wheel on Ubuntu, Windows and macOS, installs it into a
  clean virtual environment, runs `sledtrace serve`, opens the dashboard, sends
  a trace through the SDK and checks it through the API.
- The publish workflow builds the sdist, the SDK-only wheel and all six
  platform wheels, and validates the Linux wheel end to end before upload.

## Known limitations

- Python SDK only; no automatic LangChain or LlamaIndex instrumentation.
- Warnings are deterministic heuristics based on English text patterns.
- Token usage is recorded only when passed explicitly; cost estimates are
  indicative.
- Local, single-user tool without authentication or TLS.
