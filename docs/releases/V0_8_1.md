# SledTrace v0.8.1: a clearer dashboard

v0.8.1 reworks the dashboard so the most useful information comes first. The
SDK API, trace format and warning rules are unchanged.

## Highlights

- **Warnings come first.** On a trace's page the warnings now sit directly
  under the summary, in a panel whose colour matches the most serious warning,
  instead of below the usage ledger and timeline.
- **Severity everywhere.** The trace list dot and the badge on each trace show
  the same scale: green for no warnings, amber for warnings, red for high
  severity, dark red for a failed run. "No warnings" never claims the answer is
  correct.
- **A real first-run screen.** With no traces yet, the dashboard shows a
  copyable first trace (with the right collector URL filled in) instead of
  source-checkout commands.
- **Live updates.** The trace list refreshes itself every few seconds while the
  tab is visible; the Refresh button is still there.
- **Collector status.** The top bar shows whether the dashboard can reach the
  collector and turns red when `sledtrace serve` stops.
- **Less noise.** Traces without token counts fold the usage ledger into one
  line ("Token usage not recorded", still unknown rather than zero). Raw span
  JSON is folded by default. The final answer is plain text instead of a
  resizable box.
- Durations below one millisecond show as `<1ms` instead of `0ms`.
- An icon button replaces the "Hide traces" text button; the hidden list keeps
  refreshing.

## Compatibility

- The trace list API adds `high_warning_count` (warnings with severity `high`
  or `critical`). The field is additive; the dashboard also works with older
  collectors that do not send it.
- No other API, storage or SDK changes.
